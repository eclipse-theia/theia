Development and release pipeline

Trust boundaries

  1. 1Browser page or network client → backend. localhost bind, origin check, connection token (browser), security token (Electron)
  2. 8LLM output → agent tools. Tool confirmation, workspace path restriction, shell allow/denylist
  3. 2Workspace → features that run code. Workspace trust: tasks, debug, extensions, AI, MCP
  4. 9Remote hosts → local app. Opened by the user. Remote content only through the workbench and forwarded ports
  5. 3Content → workbench DOM. DOMPurify, command: links only in trusted markdown
  6. 10Workbench ↔ collaboration server and guests. Host approves each guest, optional read-only mode
  7. 4Webviews, mini-browser, notebook outputs → workbench. Separate origins, postMessage, command URI allowlist
  8. 11Contributor → published packages. Review, ECA, pinned actions, trusted publishing with provenance
  9. 5Electron renderer → Electron main. Context isolation, preload API over IPC
  10. 12Build inputs → build. Pinned versions, lockfile integrity hashes, allowScripts
  11. 6Other apps → Electron main. theia:// deep links
  12. 13Maintainer → published packages. Manual publish of new packages and fallback, npm 2FA, no provenance
  13. 7Extension source → plugin host. Installed by user, product, or CLI, then fully trusted
